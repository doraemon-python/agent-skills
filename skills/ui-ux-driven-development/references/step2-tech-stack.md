# Step 2. 技術仕様の決定と初期化

デプロイ方式などは後から変えにくい。ユーザー意図を踏まえ、今後を見据えて決める。ただし、UIを作って初めて必要性が分かる要件（リアルタイム通信、ファイルアップロードなど）もあるので、フロントエンドに影響しない決定は無理に今決めない。

ここで決めることの多くは ADR の対象になる。ADR の手順と書式は `references/adr.md` に従う。

## 手順

1. 決めるべき技術項目を、次の2つに分類する。
   1. **今決める**: フロントエンドに影響するもの、または後から変えにくいもの。例: 言語、フロントエンドのフレームワーク、フルスタックフレームワークを使うか、end-to-end の型安全の方針、バリデーションスキーマのライブラリ、認証方式の大枠、レンダリング方式、UIライブラリとスタイリング、コンポーネントカタログ（Storybook等）、テストツール、パッケージマネージャ、デプロイ先の大枠（制約が強い場合）。
   2. **後で決める**: フロントエンドに影響しないもの。例: DB製品、ORM、ホスティングの詳細、メール送信、監視。`open-questions.md` に「Step7で決める」として書く。
2. `docs/decisions/` に有効な ADR があれば読む（既存のリポジトリに導入する場合など）。案はそれと矛盾させない。変えるべきだと考える場合は、置き換え（supersede）として提案する。
3. 「今決める」項目それぞれについて、`intent.md` と非機能要件に照らして案を作る。
4. 案の候補に使うライブラリのメンテナンス状況（最近のリリース、ライセンス）を確認する。
5. 「今決める」項目のうち、ADR の対象になるものを選ぶ。基準は「後から変えにくいか、理由がコードから読み取れないか」。例: 言語とフレームワーク、レンダリング方式、認証方式、型安全の方針、デプロイ先。基準を満たさないもの（フォーマッターの選択など）は ADR にしない。1つの ADR には1つの決定だけを書く。
6. **【提案P2】** 選択肢が拮抗している項目は、2〜3案と推奨案を用意する。ADR の対象の項目は、`references/adr.md` の「3. 選択肢を示す」に従って比較する。往復を減らすため、この提案は【承認A】の依頼に含めて一度に出してよい。
7. ADR の対象の項目それぞれについて、承認依頼の「記録するADR（案）」を書く。決定、主な理由、不採用案と一行の理由、見直す条件（`revisit_if`）を書く。
8. 「Step2 決定チェックリスト」を実行する。
9. **【承認A】** ユーザー意図のまとめ（`intent.md` の要約）、技術仕様、記録するADR（案）を確認してもらう。ターンを終えて返答を待つ。
10. 承認後、プロジェクトを初期化する。依存関係のインストール、雛形の作成、型チェック・リンター・フォーマッターの設定、コンポーネントカタログの設定、テストランナーの設定を行い、データアクセス層を置くディレクトリを用意する。
11. ADR を記録する。`references/adr.md` の「5. 記録する」に従い、承認Aで確定した内容で `docs/decisions/` に書き、索引 `docs/decisions/README.md` を作る（`assets/decisions-index.md` から作る）。初期化後に書くので、`code` には実際のパス（`package.json`、設定ファイル、該当ディレクトリなど）を書ける。ユーザーが推奨案と違う案を選んだ項目は、その選択とユーザーが述べた理由で書く。
12. 「Step2 初期化チェックリスト」を実行する。
13. `progress.md` を更新し、初期化の完了と作成した ADR を簡潔に報告して Step3 へ進む（承認は不要）。

## Step2 決定チェックリスト

- [ ] 「今決める」項目すべてに案がある
- [ ] どの案も非機能要件と矛盾しない（例: オフライン編集が必要なのに、常時サーバー接続が前提の構成になっていない）
- [ ] 各案の理由を `intent.md` の記述に結び付けて説明できる
- [ ] 「後で決める」項目が `open-questions.md` に決める時期付きで載っている
- [ ] 採用するライブラリがメンテナンスされており、ライセンスに問題がない
- [ ] ADR の基準を満たす項目すべてに「記録するADR（案）」があり、決定・主な理由・不採用案・見直す条件がそろっている
- [ ] 既存の有効な ADR と矛盾する案がない（変える場合は置き換えとして明示している）

## Step2 初期化チェックリスト

- [ ] 依存関係のインストールが成功し、依存関係ファイルとロックファイルがある
- [ ] 開発サーバーが起動する
- [ ] 型チェックとリンターがエラーなく通る
- [ ] コンポーネントカタログが起動する
- [ ] サンプルテストが1つ実行でき、通る
- [ ] 承認Aで確認した ADR がすべて `docs/decisions/` にあり、内容が承認時のものと一致している
- [ ] `docs/decisions/README.md` の索引が、すべての ADR を載せている
