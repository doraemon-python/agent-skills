# Step 9. 最終確認

セキュリティ、無駄なAPIコール、不要な再レンダリングを確認したうえで、ユーザーに本物のアプリを触ってもらう。

## 手順

1. セキュリティを確認する。依存関係の脆弱性監査、全エンドポイントの認可、シークレットの混入、セキュリティヘッダー、エラーメッセージからの内部情報の漏えいを対象にする。
2. APIコールを確認する。同じデータの重複取得、不要なフィールドの取得、N+1、不要な再取得、キャッシュの有無を対象にする。
3. 再レンダリングを確認する。プロファイラで主要な画面を計測し、操作と無関係なコンポーネントの再レンダリングを減らす。計測で問題が見つかった箇所だけを対象にし、予防的なメモ化は乱用しない。
4. 見つかった問題を修正する。修正が ADR の決定を変える場合は、【承認E】の依頼の「記録するADR（案）」に含める。
5. 「Step9 チェックリスト」を実行する。
6. **【承認E】** 本物のバックエンドにつながったアプリを触ってもらう。起動方法またはURL、テスト用アカウント、試してほしい主要シナリオを具体的に書く。Step8 で控えた ADR 参照コメントの候補と、記録するADR（案）があれば、それも含める。ターンを終えて返答を待つ。
7. 承認後、同意を得た ADR を `references/adr.md` に従って記録し、同意を得た ADR 参照コメントをコードに入れる。
8. `open-questions.md` を見直して残っている事項をユーザーに伝え、`progress.md` を完了状態に更新する。

## Step9 チェックリスト

- [ ] 依存関係の脆弱性監査で、高・重大の脆弱性がない（ある場合は対応方針を書いた）
- [ ] すべてのエンドポイントで、未認証のアクセスと他人のデータへのアクセスが拒否される
- [ ] エラーレスポンスに、スタックトレースなどの内部情報が含まれていない
- [ ] シークレットがリポジトリに含まれていない
- [ ] 同じ画面で同じデータを重複して取得していない
- [ ] 一覧の取得でN+1が起きていない
- [ ] 入力のたびに不要なAPIコールが発生していない（必要に応じてdebounceなどを使っている）
- [ ] 主要な画面で、操作と無関係なコンポーネントが再レンダリングされていない（プロファイラで確認した）
- [ ] `docs/_tmp/` が空になっている
- [ ] 永続ドキュメントがすべて最新の状態になっている
- [ ] `docs/decisions/README.md` の索引が、すべての ADR の現在の `status` と一致している
- [ ] 実装が、有効な（`accepted` の）ADR の決定と食い違っていない
