# Step 5. 内部リファクタリング

コンポーネントの構造を整理する。ユーザーに見える見た目と挙動は一切変えないので、承認は求めず報告だけにする。見た目や挙動を変える必要が出た場合は、それだけを例外として【承認C】の手順で確認してもらう。

## 手順

1. 整理の対象を洗い出す。役割が重複したコンポーネント、表示とデータ取得の両方を担うコンポーネント、深いpropsのバケツリレー、命名の不統一、ディレクトリ構成の乱れ、未使用のコード・ストーリー・依存関係が対象。
2. 整理を行う。
3. ビジュアルリグレッションテストがあれば実行する。なければ、カタログの全ストーリーを目視で確認する。
4. 「Step5 チェックリスト」を実行する。
5. `progress.md` を更新し、変更の概要を簡潔に報告して Step6 へ進む。

## Step5 チェックリスト

- [ ] すべてのストーリーで、見た目と挙動がリファクタリング前と同じ
- [ ] 同じ役割のコンポーネントが複数存在しない
- [ ] 表示とデータ取得を同時に担うコンポーネントがない
- [ ] 未使用のコード、ストーリー、依存関係がない
- [ ] 型チェック、リンター、テストが通る
- [ ] Step4 チェックリストの「データ分離と型安全」の項目を、引き続きすべて満たしている
- [ ] ディレクトリ構成を変えた場合、ADR の `code` に書かれたパスが実際のパスと一致している（ずれたら `code` だけを直す）
