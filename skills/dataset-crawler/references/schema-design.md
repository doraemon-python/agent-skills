# スキーマ設計の指針と提案テンプレート

## 指針

1. **目的から逆算する**。ユーザーが比較・集計したい軸（駅別の家賃、職種別の年収、銘柄別の騰落率…）を先に挙げ、それに必要な列だけを持つ。
   「取れるから取る」列は増やさない。後から足しても `raw/` から作り直せる
2. **1 行が何か**を一文で言えるようにする（「1 物件 = 1 行」「1 銘柄 × 1 日 = 1 行」）。言えないならテーブルを分ける
3. **primary_key はサイト上の安定した ID**（URL 中の ID、銘柄コードなど）にする。物件名のような表記ゆれのある値は避ける。
   時系列は `[ticker, date]` のような複合キーにする
4. **1 対多は別テーブル**にする（求人と勤務地が複数、物件と複数の募集部屋など）。子テーブルに親の primary_key の列を持たせる。
   ただしタグ程度の単純な値の並びは `list` 型でよい
5. **単位を列名と description で固定**する（`rent_jpy`、`area_m2`、`salary_min_jpy_per_year`）。円・万円、月給・年収、税込・税抜などは必ず書く
6. **人によって判断が分かれる変換は `judgment: true`** にし、description に基準を書く。例:
   - 表記の解釈（「8万〜9万円」→ 下限？平均？、「応相談」→ 空？）
   - 分類（職種・業種・間取りを決まった値に寄せる、「駅徒歩 15 分（バス便）」の扱い）
   - 補完・計算（築年数 → 築年、和暦 → 西暦、税抜 → 税込）
7. **判断が絡む列には、元の表記を残す列も作る**（`rent_raw`、`salary_raw`）。基準を変えたとき、raw 列から機械的に作り直せる
8. **選択肢が決まる値は `enum`**。ただし最初から細かくしすぎず、「その他」を用意し、出現した値を見て後から分ける
9. **長文・書類・画像は `text` / `file` / `image`**。CSV に長文を入れると扱いにくいので、本文・PDF・図は files/ に逃がす
10. **個人情報は持たない**。求人の担当者名・電話番号、口コミの投稿者名など、目的に不要な個人に関する情報は列にしない
11. 変化を追いたいテーブルは `keep_history: true` にし、ページに `revisit_hours` を付ける

### 題材ごとの出発点

| 題材 | 1 行 | primary_key | judgment になりやすい列 | 補足 |
| --- | --- | --- | --- | --- |
| 賃貸・売買物件 | 1 掲載 | サイトの物件 ID | 賃料（管理費込みか）、間取り、築年、徒歩分数 | 同じ物件が複数サイト・複数業者に出る。名寄せは別テーブル・別工程にする |
| 求人 | 1 求人票 | サイトの求人 ID | 年収の下限・上限、職種分類、リモート可否、雇用形態 | 勤務地が複数なら子テーブル。掲載終了は `_last_seen_at` と 404（`gone`）で判断 |
| 株価・指標 | 1 銘柄 × 1 日 | `[ticker, date]` | 分割・併合の調整、決算期の対応づけ | 公式 API・CSV ダウンロードがあれば必ずそちらを使う。数値は `number` |
| 商品・価格 | 1 商品（SKU） | JAN / 型番 / サイトの商品 ID | 税込・税抜、セット商品の単価、在庫表記 | 価格推移は `keep_history: true` |
| 企業・店舗 | 1 拠点 | 法人番号 / サイトの ID | 業種分類、営業時間の正規化 | 住所は都道府県・市区町村を別列にすると集計しやすい |

## 提案テンプレート

ユーザーにはこの形で提示し、承認をもらう。表は実際の列で埋める。`probe` で見た実際の表記を例に使う。

```markdown
## データ構造の提案: <データセット名>

**目的**: <何を比較・分析するためか>
**対象**: <サイト名・範囲>（見込み: 約 <N> 件 / 取得間隔 <delay> 秒で約 <時間>）
**更新の追い方**: <一覧を毎日・詳細を週 1 回再取得 など / 追わない>
**規約・robots.txt**: <確認結果。API の有無>

### テーブル `<table>`（1 行 = <何>、キー: <primary_key>）

| 列 | 型 | 説明・単位 | 例（実際の表記 → 保存値） | 判断 |
| --- | --- | --- | --- | --- |
| site_listing_id | string | サイトの物件 ID | `/detail/123456` → `123456` | |
| rent_jpy | integer | 月額賃料（円）。管理費は含めない | `8.5万円` → `85000` | ✓ |
| rent_raw | string | 賃料欄の表記そのまま | `8.5万円` | |
| floor_plan | image | 間取り図 | files/ に保存 | |

### 判断が分かれる点と、提案する基準
1. <論点>: <基準案>（例: 「管理費込み」の賃料は内訳があれば差し引く。無ければそのまま入れて要確認にする）
2. ...

### 取らないもの
- <列にしない情報と理由>（例: 担当者名・電話番号は目的に不要な個人情報のため）

### 進め方
まず 10 ページ取得して数件を抽出し、CSV をお見せします。問題なければ 1 回あたり <N> リクエストずつ進めます。
```
